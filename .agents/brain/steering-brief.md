- `src/chemthermo/flash/_multiphase_rr.py` (new), `src/chemthermo/flash/_multiphase.py` (new), `src/chemthermo/flash/_verify.py`, `src/chemthermo/flash/_assemble.py`, `src/chemthermo/flash/_detect.py`, `src/chemthermo/flash/settings.py`, `src/chemthermo/flash/tp.py` (slice `flash-vlle-phase-addition`, ADR-0011)
  - **The phase count is now discovered up to `FlashSettings.max_phases` (new, default 3)** on the `modified-raoult` path: after any converged phase set fails its post-split stability test the incipient phase found there is added and the set re-solved; a phase whose fraction converges to zero or below is removed. `diagnostics["phase_set_history"]` records the route, e.g. `"L -> LV -> LLV"` or `"V -> LV -> LLV -> LL"`.
  - **Multiphase Rachford-Rice as a convex minimization.** The `NP-1` RR equations have a symmetric Jacobian, so they are the gradient of `F(beta) = -sum_i z_i ln t_i` (Okuno, Johns & Sepehrnoori, SPE J 15 (2010) 313), whose Hessian `A^T diag(z/t^2) A` is PSD: one minimum or none, never a spurious root. Newton inside Okuno's region `a_i . beta <= b_i`, `b_i = min(1-z_i, min_j(1-K_i^j z_i))`, derived from `x_i^j >= 0` alone - it contains **no pole**, unlike the Leibovici-Neoschil `t_i >= 0` whose boundary *is* the pole set. Initial estimate = mean of the vertices of `S` cap `{beta_j >= 0, sum beta_j <= 1}`, falling back to the vertices of `S` for a negative flash.
  - **Two deviations from the paper, both measured and recorded.** (1) The stopping test had to be made **scale free** - `max_j |f_j|` divided by `sum_i z_i |K_i^j - 1| / t_i`, floored at 1 - because `f_j` is a cancelling sum of terms of that size and one phase set holds a vapor/liquid `K` of 30 next to a liquid/liquid `K` of 1.1; with an absolute 1e-12 the n-butanol/water liquid pair stalls at 2.0e-11 and the whole flash fails. (2) The line search accepts an Armijo decrease of `F` **or** a decrease of the residual, because near the minimum the change in `F` drops below the float resolution of `F` itself. Same rule the ADR-0009 stage already used.
  - **Negative flash *is* the removal mechanism.** `S` constrains compositions, not phase amounts, so `beta_j <= 0` is a meaningful converged answer meaning "this phase is not here". No positive threshold is used: Okuno Example 3 converges to a genuine `beta = 2.2e-06`. When the region *recedes* (no minimum at all - exactly what Gibbs' rule says about three phases in a binary away from T3) the solver reports the recession and names the phase whose amount runs to minus infinity; that is the one removed.
  - **Multiphase second-order stage**: the ADR-0009 Gibbs minimization generalized from 1 to `NP-1` non-reference phases; gradient still exactly the equal-fugacity residual by the same Gibbs-Duhem cancellation. Needed: SSI alone takes **324 iterations** to reach 1e-12 on the validated tie-triangle, where the Newton stage reaches **7e-16 in 3** from a 20-iteration start.
  - **`_post_split_report` replaces the raise-only `_post_split_stability`** for the path that can add a phase, returning the instabilities and their minimizers; the old function keeps the old message for phi-phi and gamma-gamma. The partner-is-marginal rule now reads *every* other phase (identical for two).
  - **Bit-identity was the binding constraint on the diagnostics contract.** The new keys (`phase_set_history`, `phases_added`, `phases_removed`, `delta_g_vs_two_phase_rt`, `rachford_rice_iterations`) appear **only** on results that actually entered the search, because `tests/test_flash_refactor_bit_identity.py` compares whole `diagnostics` mappings with `==` and any added key on an existing path would break it.

- `src/chemthermo/models/_antoine.py` (new), `src/chemthermo/stability/_evaluator.py`, `src/chemthermo/stability/tp.py`, `src/chemthermo/flash/_detect.py`, `src/chemthermo/flash/_split.py`, `src/chemthermo/flash/_second_order.py`, `src/chemthermo/flash/_verify.py`, `src/chemthermo/flash/tp.py`, `src/chemthermo/flash/settings.py` (slice `flash-modified-raoult`, ADR-0010)
  - **Phase candidates.** The internal tangent-plane evaluator now holds a *set* of `_PhaseCandidate`s and `_select_min_gibbs` keeps the one minimizing `sum_i w_i term_i(w)` - the only candidate-dependent part of `G/RT`. That is one rule for three families: the cubic's two compressibility roots, a single activity liquid (label `None`, because nothing was selected), and the new modified-Raoult pair. The EOS and activity-only adapters are the two-candidate and one-candidate special cases, with the same float operations, the same order and the same error strings; the flash bit-identity fixture and the pinned Peng-Robinson stability numbers are untouched. A candidate's `optional` flag separates "this root may not exist here" (skipped) from "this model failed" (re-raised) - the second case must not be answered with the *other* candidate.
  - **`stability_tp(..., activity_model=..., vapor="ideal")`**: adds an ideal-gas candidate to the activity liquid, whose term becomes `ln gamma_i + ln(Psat_i/P)` with `Psat` from the databank Antoine records. `feed_branch`/`phase_branch` then say `"liquid"`/`"vapor"` - i.e. what the feed *is* and what the incipient phase *is*. `vapor="ideal"` with an `eos` is a `ModelError`; full gamma-phi against an EOS vapor is still refused (ADR-0007 is narrowed, not overturned).
  - **`flash_tp(..., flash_mode="modified-raoult")`**: the candidate labels decide the regime, so VLE returns `liquid`/`vapor` with a real `vapor_fraction` and LLE returns `liquid1`/`liquid2` with `None` - no volatility-ordering heuristic is needed here, unlike phi-phi. The split gives each phase its assigned candidate and the K update collapses to `K_i = exp(t_i^x(x) - t_i^y(y))`, which *is* `gamma_i Psat_i / P` for a liquid/vapor pair and `gamma_i^I/gamma_i^II` for two liquids. The ADR-0009 second-order stage was generalized to two term functions (gamma-gamma passes the same one twice, so nothing moved there). Post-split re-tests **both** phases against **both** candidates. The mode is deliberately **never inferred**: an activity model alone still means `gamma-gamma`.
  - **Antoine is enforced, not extrapolated.** `ln(P^sat/bar) = A - B/(T+C)` (Koretsky 2012; water gives 1.0131 bar at 373.15 K). Outside `[Tmin_K, Tmax_K]` the call raises `InputRangeError`; the mixture's window is reported in diagnostics.
  - `flash_mode="gamma-phi"` marked **DEPRECATED** in docstrings and README, with the physical reason (it multiplies `gamma` by an EOS liquid `phi`, double-counting the liquid's nonideality, and carries no pure-liquid reference fugacity at all). Nothing about it changed; the CLI is untouched.

## Current architecture (8-12 lines)
- `NRTL` implements the standard Renon-Prausnitz equation (column sums); it satisfies Gibbs-Duhem to ~2e-10 and matches `thermo` to ~9e-16 with asymmetric parameters. Packaged pair parameters are synthetic placeholders; published sets live in `tests/fixtures/`.
- `PengRobinsonEOS.kij` is a scalar (off-diagonal only) or a name-keyed per-pair `Mapping`; `flash_tp` and `stability_tp` results for nonzero kij are now trustworthy (ADR-0006).
- Phase stability (`chemthermo.stability`) is a solver-independent sibling of `chemthermo.flash`, and `flash_tp` consumes it twice: `flash_tp -> stability_tp -> split -> post-split stability` (ADR-0008, ADR-0009, ADR-0010), for phi-phi (EOS), gamma-gamma (activity, liquid-liquid) and modified-raoult (activity liquid + ideal vapor, VLE *or* LLE) alike. It serves all three through the internal `_TangentPlaneEvaluator` contract, which now holds a *set* of `_PhaseCandidate`s and keeps the lowest-Gibbs one at each composition (min-Gibbs cubic root; single liquid; liquid-versus-vapor). Each trial runs successive substitution then an optional damped-Newton stage.
- `Psat_i(T)` from the databank Antoine records lives in `src/chemthermo/models/_antoine.py` (internal), in the stored form `ln(P^sat/bar) = A - B/(T+C)`; it is the modified-Raoult reference fugacity and is refused outside each fit's stated range.
- Canonical runtime DB path is `src/chemthermo/data/components.json`.
- Runtime DB loading is package-resource based via `chemthermo.data` helpers.
- Raw DB source tables stay in `database/organics.txt` and `database/inorganics.txt`.
- `tools/build_database.py` is the canonical regeneration/check tool for packaged DB sync.
- Optional mirror output path is `database/components.mirror.json` (non-runtime, generated-only).
- Core thermodynamic flow is `Component/Composition/Mixture -> models -> flash_tp -> stability_tp -> seeded split (+ second-order stage for LLE) -> post-split stability -> FlashResult` (phi-phi and gamma-gamma); gamma-phi still goes straight to the Wilson-seeded split and is not post-split checked.
- CLI `tp-flash` maps inputs to `Mixture + PengRobinsonEOS + flash_tp`, with optional `NRTL()` activity model when `--flash-mode gamma-phi`.
- CLI supports deterministic text/json outputs with schema version and diagnostics.
- External validation remains optional and script-driven (`examples/validation/00_reference_case.py`).

## Public API status (stable vs experimental)
- Stable:
  - `chemthermo` Python exports in `src/chemthermo/__init__.py`, including `stability_tp` / `StabilityResult` / `StabilitySettings` / `StabilityTrial` (ADR-0005, ADR-0007). `stability_tp` takes exactly one of `eos=` / `activity_model=`.
  - `PengRobinsonEOS(kij=...)` scalar-or-mapping constructor contract (ADR-0006).
  - `FlashSettings(phase_detection=..., stability_settings=...)` and the `flash_tp` diagnostics keys listed in its docstring (ADR-0008).
  - `flash_tp(..., eos=None, activity_model=..., flash_mode=None)` liquid-liquid mode, the `liquid1`/`liquid2` role naming, `vapor_fraction=None` for gamma-gamma, the post-split diagnostics keys, and `FlashSettings(post_split_stability=..., second_order=..., ssi_iterations=..., second_order_max_iter=..., second_order_tol=...)` (ADR-0009).
  - `flash_tp(..., flash_mode="modified-raoult")` and `stability_tp(..., activity_model=..., vapor="ideal")`, the `"liquid"`/`"vapor"` candidate labels in `feed_branch`/`phase_branch`, `model_family == "modified-raoult"`, and the `antoine_valid_Tmin_K` / `antoine_valid_Tmax_K` diagnostics (ADR-0010).
- Deprecated (unchanged, not removed):
  - `flash_mode="gamma-phi"`. Double-counts liquid nonideality and has no pure-liquid reference fugacity; use `"modified-raoult"` at low pressure and `"phi-phi"` at high pressure. Removal would need its own ADR.
  - `chemthermo.eos` and `chemthermo.vlle` documented public subpackages.
  - CLI script `chemthermo` with `tp-flash` subcommand and defined exit-code contract.
- Experimental/placeholder:
  - PC-SAFT residual Helmholtz implementation remains placeholder in open-source build.
  - Validation policy promotion to required CI remains deferred.

## Risks / unknowns
- **Near a three-phase state the modified-Raoult path refuses over a finite window, and its message is only half right.** Measured for water/1-butanol at 1 atm, z(butanol) = 0.20: from about T3 - 0.135 K up to T3 = 366.2138 K, the deepest tangent-plane minimum is the *vapor*, the split converges a vapor-liquid pair whose liquid lies inside the miscibility gap, and the post-split test raises "a third phase is required". Refusing is correct (that pair is not the equilibrium), but below T3 the resolution is a *different pair of two*, reached by adding the second liquid and then removing the vapor. `flash-vlle-phase-addition` must handle removal, not only addition. Validation Case R-3, ADR-0010 "Known limitation, measured".
- The modified-Raoult model is honest only at low pressure: ideal vapor (no `phi^V`), no Poynting correction, no `phi^sat`, and a temperature range bounded by the Antoine fits (enforced with `InputRangeError`, never extrapolated). Nothing in the code stops a user from calling it at 50 bar; the docs say not to, and the physics does not.
- `flash_tp` still returns at most two phases. A state needing a third is now *detected* by the post-split check and refused with `ConvergenceError`, not solved. Both the feed verdict and the post-split verdict inherit `stability_tp`'s bound: "stable" means nothing negative was found from the deterministic trial set, so a third phase no trial reaches would still be missed.
- The post-split check is only as sharp as the split it checks. Measured margin at default settings is large (worst post-split `tpd_min` -7.0e-09 against `tpd_tol` 1e-8 - a factor of 1.4 - with the minimizer matching the partner phase to `sum ln(w/x)^2 <= 4e-16`, twelve orders inside `trivial_tol`), but with a deliberately loosened `FlashSettings(tol=1e-3)` a genuinely two-phase state is reported as needing a third phase. Documented in README and ADR-0009.
- Every two-phase flash on the tangent-plane paths now pays for two extra stability analyses (measured: 0.9 s for the 47 two-phase states of the in-repo grid, roughly doubling their cost). There is no way to skip the computation, only the raise.
- `liquid1`/`liquid2` carry no physical identity and can swap between feeds on the same tie-line. Any consumer that indexes `result.phases["liquid1"]` expecting a particular liquid is wrong.
- The vapor/liquid *name* of a `flash_tp` phase is a convention in two places: a single-root (dense/supercritical) single-phase feed gets whichever branch label wins the min-Gibbs tie-break, and a two-phase result is named by Wilson volatility ranking. `EquationOfState` exposes no molar volume, so nothing better is available without widening that protocol.
- Every phi-phi flash now pays for a stability analysis (2 Wilson trials + 1 pure trial per component) even for an obviously single-phase feed.
- 5 states in the 1144-state scan (Methane/Propane/n-Decane 0.7/0.2/0.1 at 1.2e7-2.0e7 Pa) split in chemthermo (`delta_g_split_rt < 0`) while `thermo`'s `FlashVL` returns `VF = 0`. They disagreed with `thermo` before this slice too, so they are not caused by it. Now adjudicated: evaluating `thermo`'s own `lnphis_at_zs(..., most_stable=True)` at chemthermo's `stability_tp` minimizer gives a negative tpd (within 5e-5 abs of chemthermo's `tpd_min`) at all 5 states, so `thermo`'s `VF = 0` is a stability-*search* miss on `thermo`'s side, not a chemthermo error. See Case F-1 in `validation-cases.md` and `tests/validation/test_flash_thermo_disagreements_adjudicated.py`.
- `stability_tp` reporting "stable" is bounded by its deterministic trial set; it is not a global proof, and the docs must keep saying so. Measured limit: on Tessier (2000) Problem 2 the trial set reaches 7 of the 10 non-trivial published stationary points; the three it misses all have D > 0 (Cases S-6, S-7).
- Combined gamma-phi stability (activity liquid vs EOS vapor) raises `ModelError`. It stays unsupported until there is a consistent pure-liquid reference fugacity (ADR-0007); the current gamma-phi flash does not carry one correctly.
- The second-order stage uses a central-difference Jacobian of `ln phi`/`ln gamma`. For a cubic EOS the min-Gibbs branch can switch between finite-difference probes, which would make that Jacobian noisy; it has not been observed because every validated PR state converges inside the 50-iteration SSI budget and never enters the stage. Watch for it if PR states that need the stage ever appear.
- chemthermo uses the rounded PR constants 0.45724 / 0.07780 while `thermo` uses the exact roots; this bounds external agreement at a few times 1e-4 in ln(phi) (was ~2e-4 at the stability states, ~4-6e-4 at some nonzero-kij states -- see Case K-1).
- The illustrative kij value used in docs/examples/tests (0.0411, Methane/n-Decane) is explicitly NOT a validated literature parameter -- do not let it drift into being read as one.
- `thermo`'s own `CEOSLiquid`/`CEOSGas` root solver was observed to be numerically order-sensitive (not permutation-invariant) at some near-critical-locus states during `pr-kij-matrix` development; avoid cross-checking permutation invariance against `thermo` at such states (use chemthermo-internal invariance checks instead, as `tests/validation/test_pr_kij_vs_thermo.py` now does).
- CLI JSON contract must remain backward-compatible or version-bumped.
- DB builder currently assumes raw table column conventions stay unchanged.
- Optional validation still depends on external `thermo` package availability.
- (Removed) Unpinned `bibtexparser>=1.4.0` allowed a fresh/non-editable install to resolve `bibtexparser` 2.x, whose removed `bparser`/`customization` modules broke `import chemthermo`; this was invisible locally because the dev venv already had 1.4.4 installed. Now pinned to `>=1.4.0,<2` and covered by `tests/test_packaging_constraints.py`.

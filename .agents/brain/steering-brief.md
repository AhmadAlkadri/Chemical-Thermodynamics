- `src/chemthermo/stability/_evaluator.py`, `src/chemthermo/stability/tp.py`, `src/chemthermo/stability/results.py` (slice `stability-eos-root-surfaces`, ADR-0021)
  - **ADR-0012's rule finally applies to the equation-of-state family, and ADR-0012's reason for exempting it does not survive the measurement.** It argued that a missing compressibility root is "the same model failing to be evaluable", unlike the modified-Raoult pair's two different models, and concluded that minimum-Gibbs root selection per iterate should stay. The first half is right; the second does not follow, because the property that breaks the fixed-point map is **discontinuity**, not model identity. Case P-9 (iv) is the same failure in the same shape: PC-SAFT water / n-hexane at 1 atm, `z_water = 0.7`, 335 K returned two liquids metastable by **2.495e-03 RT** because every trial from the hexane-rich liquid slid onto the liquid root, while a vapour stationary point at `tpd = -6.5237e-03` sat unvisited. ADR-0021 pins `wilson-vapor` to the vapour root and `wilson-liquid` / `pure-<name>` to the liquid root; the trial now reaches that point in **7 iterations** and `flash_tp` returns the vapour-liquid pair (`G(VL)/RT = -1.164306` against `-1.161811`).
  - **The fallback ADR-0012 worried about is real and benign, and the interesting number is how often it fires.** Where a model has one admissible density root, `PengRobinsonEOS` and `PCSAFTEOS` both answer `phase="vapor"` and `phase="liquid"` with the *same* numbers, so a pinned trial walks the only surface there with no exception and no wrong phase. Instrumented once with a both-branches build: **3889 single-root evaluations against 4378 trial iterations** on the Peng-Robinson grid, **14975 against 16898** on the PC-SAFT one - different denominators, so read it as about nine in ten rather than an exact percentage. The fixed surface therefore changes the iteration only in the remaining tenth, and that tenth is exactly where P-9 (iv) lived.
  - **A cost decision, stated rather than hidden.** Counting that fallback at *every* iterate needs both branches evaluated at every iterate, which is what the min-Gibbs rule used to cost. That version was implemented first, produced **bit-identical** results (the iterate walks the same root either way), and put `pytest -q` at 311 s against a 244 s baseline. What ships evaluates one root per iterate and counts the condition where the solver compares the branches anyway - the trial's stopping point, in the new `_TangentPlaneEvaluator.ln_report_terms`. So `StabilityTrial.surface_fallback` / `surface_fallback_count` mean "this trial stopped where the model had no second root" (448 / 624 Peng-Robinson trials, 589 / 752 PC-SAFT), not "it never left its surface"; the nine-in-ten figure lives in ADR-0021 and Case P-11 instead of in a diagnostic nobody would pay for.
  - **The slice made the EOS stability test cheaper, not dearer.** One root per iterate instead of two: `stability_tp` over the 188-state Case F-4 grid **76.6 s -> 44.3 s** (-42 %), `pytest -q` **244.2 s -> 231.7 s** before the new golden path is added, **247.3 s for 750 tests** with it (against 244.2 s for 738). Trial *iterations* went up (+7.3 % PR, +3.7 % PC-SAFT) because trials that used to collapse onto the feed now walk to a real stationary point.
  - **Nothing previously validated moved, and that was checked three ways before the fixture was touched.** 144-state Peng-Robinson stability grid: 0 verdict changes, 0 branch-label changes, worst `|d tpd_min|` 1.8e-15, worst `|d w|` 7.3e-12. 188-state PC-SAFT grid: 0 and 0, 1.2e-12 and 2.2e-15. A 1144-state Peng-Robinson `flash_tp` scan (8 mixtures x 11 T x 13 P): **0 verdict changes, 0 `ConvergenceError` before and after**, worst composition move 1.1e-15, phase fractions identical.
  - **The one thing that does change cannot change a verdict.** On 18 / 144, 38 / 188 and 118 / 1144 states, `tpd_min` moves from `0.0` - the value the summary reports when no non-trivial stationary point was reachable - to a **positive** number (smallest 0.0968 on the wide scan). - `src/chemthermo/flash/_multiphase.py`, `src/chemthermo/flash/_detect.py` (slice `flash-phase-addition-eos`, ADR-0020)
  - **The phase addition/removal search stopped being a `modified-raoult` privilege.** ADR-0011 built it, wired it to one path, and said why: nothing in this repository exercised a third phase on phi-phi. ADR-0018 (association) and ADR-0019 (per-phase density roots) supplied the states, and ADR-0019 bracketed them rather than guessing - PC-SAFT water / n-hexane at 1 atm raised `ConvergenceError` at 330 K and 334 K. Those temperatures now return verified answers, and so do all 82 states of a two-feed scan across `[T3 - 1 K, T3 + 1 K]`.
  - **The generalization is one idea: a phase carries its own model surface.** The loop used to hold a `Mapping[label, callable]` and look each phase's term function up by label, which cannot express a three-phase EOS set - two of its phases carry the label `"liquid"` and are different phases on different density roots. It now holds a list of surfaces parallel to its labels, minted by `_PhaseSetModel.surface(label)`. `_ActivityPhaseSet`: a label names a phase *candidate* and **is** the identity. `_EosPhaseSet`: a label names a *density root*, each phase gets its own ADR-0019 `_PhaseRoot` pinned to it, and the identity is **measured** with `phase_identity` (ADR-0017). The two phases handed over from the two-phase split keep the very holders that split used.
  - **The binary window is the Case R-3 mechanism on an equation of state, not a three-phase region.** Gibbs' phase rule gives a binary at fixed pressure one degree of freedom, so three phases meet at a single temperature and the three amounts there are *underdetermined* - no three-phase `FlashResult` is produced or claimed for the binary. Below `T3` the search runs `V -> LV -> LLV -> LL`: the deepest tangent-plane minimum from the feed is a vapour, the pair is unstable towards a second liquid, and the three-phase solve then drives the vapour amount negative. The answer is the two conjugate liquids, matching an independent two-equation Newton to **2.3e-13** and the lever rule to **1.2e-13**, with `G(LL) < G(VL) < G(feed)` and `delta_g_vs_two_phase_rt` exactly `G(LL) - G(VL)`.
  - **`T3` is recomputed here, not taken from anywhere.** A 4-equation Newton in `(x^I, x^II, y, T)` on the public `fugacity_coefficients` gives `T3 = 334.807826336 K` (residual 1.7e-12), and bisecting `flash_tp`'s own LLE/VLE verdict puts the switch **2.4e-07 K** below it. At `T3` every one of the three coexisting compositions has *both* a vapour and a liquid density root, which is the premise of ADR-0019's per-phase pinning shown rather than asserted.
  - **FeOs's own flash prefers the metastable pair here, and that is reported.** Below `T3`, `State.tp_flash` converges on the vapour-liquid pair - the one chemthermo converges first and then refuses - which chemthermo reproduces to 6.3e-10 with `post_split_stability=False`. Both are stationary states of the same model; the Gibbs comparison decides, and it prefers the two liquids by 1.081e-03 RT. FeOs's chemical potentials at chemthermo's phases: **6.8e-11** matched, 2.2e-06 as shipped.
  - **Genuine three-phase answers are ternary, and there are two.** PC-SAFT water / ethanol / n-hexane at 333 K and 1 atm returns a `VLLE` tie triangle - 9 of 36 grid feeds, independent 6-equation Newton to **2.6e-11**, amounts from an independent mass balance to **5.5e-11**, FeOs potentials to **1.4e-11**, `G3 < G2 < G1`. And **Peng-Robinson with `kij = 0`** on the same ternary at 280 K returns three *liquids* in 0.1 s, which discharges ADR-0019's "no pure Peng-Robinson three-phase case found in the databank".
  - **One new search rule, added because a state demanded it.** At 330 K the deepest minimum found from the vapour is the water-rich liquid *already in the set*; the multiphase Rachford-Rice removes it before it can move and the search cycles `LV -> LLV -> LV -> ...`. When the phase just added is the phase the next solve removes, the **next** stationary point of the same report is tried instead, each at most once - which terminates with the phase count, unlike the open-ended retry ADR-0011 rejected.
  - **Two limitations recorded rather than worked around.** (1) At `z_water = 0.7` above `T3` the answer is two liquids whose Gibbs energy is **2.5e-03 RT above** the vapour-liquid pair's: all four `_EOSTangentPlane` trials from the hexane-rich liquid reach only the trivial solution or its partner while the vapour stationary point sits at `tpd = -6.5e-03`. A stability-trial-set limitation (ADR-0012 left the EOS family without fixed surfaces), pinned so that fixing it is noticed. (2) One ternary feed of 36 raises - and raised before this slice too.
  - **Bit-identity by non-entry.** The search runs only after a post-split failure, and every state of the 155-state fixture and of the PR / PC-SAFT grids is post-split stable. The fixture passes unchanged (no v3), and a test asserts directly on the fixture JSON that no pinned state carries a key the search produces.
  - **Runtime.** `pytest -q` went **337 s -> 238 s** (733 -> 738 tests) while gaining a three-phase capability, by giving six heavy examples a `--full` flag with a cheaper default (the ADR-0017 pattern) and marking nine *repetitions* `slow`. `.agents/dev-contract.md`'s rule for the marker is widened accordingly, and says so. `pytest -q -m slow` is now 21 tests in 855 s (14:14).
- `src/chemthermo/flash/_split.py`, `src/chemthermo/flash/_detect.py`, `src/chemthermo/flash/_verify.py` (slice `flash-eos-per-phase-roots`, ADR-0019)
  - **The phi-phi split could only ever describe a vapour-liquid pair, and now it cannot only do that.** `_split._ln_phi_function` evaluated one phase with `phase="liquid"` and the other with `phase="vapor"`, at every iterate, so wherever a vapour density root exists a liquid-liquid answer was inexpressible. Water / n-hexane at 298.15 K and 1 atm (two density roots at the feed: 43.01 and 13,419.37 mol/m^3) converged on a water-rich liquid against a hexane-rich **vapour** with `delta_g_split_rt = +0.259`, and the post-split stability test refused it - correctly, with a message naming the wrong disease. That was Case P-7(iii), recorded and left standing by the association slice's brief.
  - **The fix is per-phase bookkeeping, not a new solver.** `_split._PhaseRoot` holds one phase's branch; `_detect._phi_phi_roots` builds two and pins each to the branch `stability_tp` reported for *that* phase - `feed_branch` for the feed-like one, `phase_branch` for the incipient one, mapped through `diagnostics["incipient_phase"]` because `_stability_k_seed` may orient `x`/`y` either way. For water / n-hexane at 1 atm both are `"liquid"`, which is exactly the information the old code discarded. The same two holders are handed to the ADR-0016 second-order stage and to the naming rule, so every evaluation of a phase - SSI, the Newton stage's energy/gradient/Hessian, and the final verification - is on one root.
  - **Why the branch is *held* rather than re-selected per iterate, with the measurement that decided it.** The literal Michelsen & Mollerup rule (each phase on its lowest-Gibbs root, every evaluation) was implemented first and **breaks the ADR-0016 reference state**: PC-SAFT CO2 / n-decane `z = (0.9, 0.1)` at 240 K / 1 MPa walks the liquid phase to `x = (0.99066, 0.00934)` at the fifteenth iterate, where the vapour root has the lower Gibbs energy; both phases then sit on one root at nearly one composition and the split runs away to `beta = -3.2e+09`. Three ADR-0016 states, three F-4 grid states, the 16-state subset and both teqp cross-checks failed with it. Holding the branch is ADR-0012's fixed-surface rule applied to the split, for the same reason ADR-0012 gave; the lowest-Gibbs rule survives as the fallback when the pinned branch is unusable, and as the **check**, because `_post_split_stability` re-tests every converged phase with it. `delta_g_split_rt` became exact rather than an upper bound as a side effect.
  - **Naming.** `_name_two_phase_result` asks `phase_identity` on the root each phase converged on: one of each -> `"liquid"` / `"vapor"` as before; **both liquids -> `liquid1` / `liquid2`, `vapor_fraction = None`, `phase_regime = "LLE"`**; both vapours or no measurement -> the ADR-0008 Wilson-ranking fallback, kept and exercised by a test with a `phase_identity`-less subclass. The LLE order is **composition-based** (larger mole fraction of the first component, ties broken by the next), unlike the gamma-gamma path's seed roles, so three feeds on one tie line come back with the same labels - which is what makes the lever-rule comparison meaningful. That the two paths now mean different things by `liquid1` is documented in `flash_tp` rather than smoothed over.
  - **New diagnostics keys `phase_i_branch` / `phase_ii_branch`, conditional.** They carry the ADR-0017 *identity* of each converged root (not the raw candidate label, which on a single-root state is a tie-break between two names for one thing and would fire on states where nothing moved - measured: methane / n-pentane 360 K / 8 MPa), and appear only when that pair is not `("liquid", "vapor")`. Same principle as ADR-0016's four stage keys.
  - **Bit-identity, two independent claims.** Outputs: `tests/test_flash_refactor_bit_identity.py` passes **unchanged** against `refactor_bit_identity_v2.json` - no v3 was needed and none was written, so the slice's audit policy never fired. Arithmetic: a new property test replays all 144 Peng-Robinson phi-phi states of that fixture with `_PhaseRoot` instrumented and asserts that on all **47** two-phase states, at **every** iterate, each phase's coefficients are `==` the ones the old fixed assignment would have produced (the other 97 are single-phase and build no holder). Two near-misses found while proving it and fixed rather than tolerated: re-normalizing an already-normalized composition moved one grid state in the fifteenth digit (the holder now passes the loop's array through untouched; only `ln_fugacity_terms`, which replaces a callable that did normalize, normalizes), and the `K = phi^x / phi^y` update keeps its floating-point spelling rather than becoming `exp(t^x - t^y)`.
  - **What it buys, measured.** At 1 atm the tie line, densities and phase amounts match **FeOs's own `tp_flash`** to 6.3e-09, 5.4e-09 relative and 3.2e-09, and FeOs's chemical potentials at chemthermo's phases are equal to **5.3e-12** with matched universal constants (2.6e-06 as shipped - the constants table, not either solver). The 1 MPa tie line keeps its Case P-7 numbers and loses its `wilson-ranking` mislabel. **Peng-Robinson** with `kij = 0` gains the same capability with no model change: at 298.15 K / 1 atm the same binary returns a verified split (`delta_g_split_rt = -1.1217`, post-split stable) where it previously raised - what that model *predicts* there (essentially zero hexane in water) is reported, not asserted.
  - **What is deliberately out.** No phase addition: a genuinely three-phase EOS state still raises. That window is now bracketed on the same binary at 1 atm - 322/324/326/328 K stable LLE, 335/336/340/350 K stable VLE, **330 K and 334 K raise** - and is the next slice's target.

- `src/chemthermo/eos/_pcsaft_association.py` (new), `src/chemthermo/eos/pcsaft.py`, `src/chemthermo/eos/_pcsaft_density.py`, `src/chemthermo/parameters/pcsaft.py`, `src/chemthermo/parameters/data/eos/pcsaft.json` (slice `pcsaft-association`, ADR-0018)
  - **PC-SAFT stopped refusing a whole class of fluids.** The association term of Gross & Sadowski, *IECR* **41** (2002) 5510 is in, so water and the C1-C4 1-alkanols are usable components. Five packaged records gained an `association` block (Water, Methanol, Ethanol, 1-Propanol, n-Butanol), all 2B (`na = nb = 1`). Nothing about the call signatures changed; a mixture containing one of them simply gets the extra term, in `A^res/RT`, `Z` and `ln phi_i`, in the `(T, rho, x)` path **and** in the packing-fraction path the density-root solver uses.
  - **Derivatives are Michelsen & Hendriks (FPE 180 (2001) 165), not implicit differentiation.** Their stationary `Q(X)` makes every *first* derivative of `a_assoc` the explicit partial of `Q` at frozen site fractions - no implicit differentiation of the mass-action system for the density or for any composition. The one place stationarity does not help is `a''(eta)`, which needs the site-fraction sensitivity; it is `Q_eta_eta - (w .* F_eta) . (J^-1 F_eta)`, one back-substitution on the Newton Jacobian the site solve already assembles. **Analytic, no finite difference in shipped code** - `a''` is what `dP/drho` and therefore the mechanical-stability filter are built from.
  - **`sigma_ij^3`, not `d_ij^3`, settled numerically because the paper could not be read.** `pubs.acs.org` returns HTTP 403 for DOI 10.1021/ie010954d, as it did for the 2001 paper. Both prefactors are in circulation and they differ by 0.93 % in the cube and 0.16 % in `a_assoc` at a liquid density (water's `d` is 2.9915 A against `sigma = 3.0007`). Measured at 300 K / 55 kmol/m^3: `sigma^3` reproduces FeOs's association term **exactly** (0.0 in double precision) and `d^3` is **8.9e-03** away. The cross rules are Wolbach-Sandler, confirmed against a *third* source - Clapeyron.jl stores the water/ethanol cross pair explicitly (2577.05 K, 0.03356196748232913) and the rules reproduce both digit for digit from the two pure records; the plain geometric mean does not, and using it moves `a_assoc` by 5.8e-04 for a 0.5/0.5 liquid.
  - **The site solve is 12 damped substitutions then batched Newton on an O(1) residual, tolerance 1e-14.** Written as `X(1 + rho Delta W X) - 1` rather than `1/X - 1 - ...` so one absolute tolerance means the same thing in a dilute gas and in liquid water (`X ~ 0.01`). Vectorised over leading axes, so the whole 1599-point scan grid is one call and one batched `np.linalg.solve`. Measured: plain undamped substitution needs 926 steps for pure water at 300 K / 55 kmol/m^3 and **does not converge in 200,000 steps** for a 0.2/0.8 water/ethanol liquid (the map oscillates); the shipped solver reaches a worst mass-action residual of **4.4e-16** over the full grid.
  - **ADR-0014 bit-identity is by construction**: `build_setup` returns `None` when no component carries sites, and both call sites then evaluate the pre-slice expression. n-hexane's pinned `A^res/RT`, `Z`, `ln phi` and density roots are asserted with `==`, not `approx`.
  - Two new inspection methods, `PCSAFTEOS.residual_helmholtz_terms(...)` and `PCSAFTEOS.site_fractions(...)`, plus `association_parameters()` / `associates()` and the new public `PCSAFTAssociationRecord`. They exist because the association term is what this slice validates *term by term*; without an accessor a caller could only ever see the sum.

- `src/chemthermo/flash/_multiphase_rr.py` (new), `src/chemthermo/flash/_multiphase.py` (new), `src/chemthermo/flash/_verify.py`, `src/chemthermo/flash/_assemble.py`, `src/chemthermo/flash/_detect.py`, `src/chemthermo/flash/settings.py`, `src/chemthermo/flash/tp.py` (slice `flash-vlle-phase-addition`, ADR-0011)
  - **The phase count is now discovered up to `FlashSettings.max_phases` (new, default 3)** on the `modified-raoult` path: after any converged phase set fails its post-split stability test the incipient phase found there is added and the set re-solved; a phase whose fraction converges to zero or below is removed. `diagnostics["phase_set_history"]` records the route, e.g. `"L -> LV -> LLV"` or `"V -> LV -> LLV -> LL"`.
  - **Multiphase Rachford-Rice as a convex minimization.** The `NP-1` RR equations have a symmetric Jacobian, so they are the gradient of `F(beta) = -sum_i z_i ln t_i` (Okuno, Johns & Sepehrnoori, SPE J 15 (2010) 313), whose Hessian `A^T diag(z/t^2) A` is PSD: one minimum or none, never a spurious root. Newton inside Okuno's region `a_i . beta <= b_i`, `b_i = min(1-z_i, min_j(1-K_i^j z_i))`, derived from `x_i^j >= 0` alone - it contains **no pole**, unlike the Leibovici-Neoschil `t_i >= 0` whose boundary *is* the pole set. Initial estimate = mean of the vertices of `S` cap `{beta_j >= 0, sum beta_j <= 1}`, falling back to the vertices of `S` for a negative flash.
  - **Two deviations from the paper, both measured and recorded.** (1) The stopping test had to be made **scale free** - `max_j |f_j|` divided by `sum_i z_i |K_i^j - 1| / t_i`, floored at 1 - because `f_j` is a cancelling sum of terms of that size and one phase set holds a vapor/liquid `K` of 30 next to a liquid/liquid `K` of 1.1; with an absolute 1e-12 the n-butanol/water liquid pair stalls at 2.0e-11 and the whole flash fails. (2) The line search accepts an Armijo decrease of `F` **or** a decrease of the residual, because near the minimum the change in `F` drops below the float resolution of `F` itself. Same rule the ADR-0009 stage already used.
  - **Negative flash *is* the removal mechanism.** `S` constrains compositions, not phase amounts, so `beta_j <= 0` is a meaningful converged answer meaning "this phase is not here". No positive threshold is used: Okuno Example 3 converges to a genuine `beta = 2.2e-06`. When the region *recedes* (no minimum at all - exactly what Gibbs' rule says about three phases in a binary away from T3) the solver reports the recession and names the phase whose amount runs to minus infinity; that is the one removed.
  - **Multiphase second-order stage**: the ADR-0009 Gibbs minimization generalized from 1 to `NP-1` non-reference phases; gradient still exactly the equal-fugacity residual by the same Gibbs-Duhem cancellation. Needed: SSI alone takes **324 iterations** to reach 1e-12 on the validated tie-triangle, where the Newton stage reaches **7e-16 in 3** from a 20-iteration start.
  - **`_post_split_report` replaces the raise-only `_post_split_stability`** for the path that can add a phase, returning the instabilities and their minimizers; the old function keeps the old message for phi-phi and gamma-gamma. The partner-is-marginal rule now reads *every* other phase (identical for two).
  - **Bit-identity was the binding constraint on the diagnostics contract.** The new keys (`phase_set_history`, `phases_added`, `phases_removed`, `delta_g_vs_two_phase_rt`, `rachford_rice_iterations`) appear **only** on results that actually entered the search, because `tests/test_flash_refactor_bit_identity.py` compares whole `diagnostics` mappings with `==` and any added key on an existing path would break it.

A residual system cannot distinguish the equilibrium from the trivial solution; a descent method on `g` can. The stage is wired to the liquid-liquid split **only**, so no phi-phi number moved.

## Current architecture (8-12 lines)
- `chemthermo.eos.PCSAFTEOS` speaks **both** state specifications: `(T, molar density, x)` in for `A^res/RT` / `Z` / `P` / `ln phi_i` (ADR-0014), and `(T, P, x, phase)` in for `fugacity_coefficients` / `density_roots` / `molar_volume` (ADR-0015), the latter solving `P_model = P` for its mechanically stable roots in the private `eos/_pcsaft_density.py` (the model restricted to one `(T, x)` is a function of the packing fraction alone, which makes the scan vectorizable and `dP/drho` analytic). Because it now satisfies `chemthermo.models.EquationOfState`, it joins the flash and the stability test **through the same interface Peng-Robinson uses and with no solver change**: `_EOSTangentPlane`'s existing lowest-Gibbs selection over the `"vapor"` / `"liquid"` branches is already the right rule for density roots. It shares the `kij` contract with Peng-Robinson through the internal `models/_kij.py`.
- `NRTL` implements the standard Renon-Prausnitz equation (column sums); it satisfies Gibbs-Duhem to ~2e-10 and matches `thermo` to ~9e-16 with asymmetric parameters. Packaged pair parameters are synthetic placeholders; published sets live in `tests/fixtures/`.
- `PengRobinsonEOS.kij` is a scalar (off-diagonal only) or a name-keyed per-pair `Mapping`; `flash_tp` and `stability_tp` results for nonzero kij are now trustworthy (ADR-0006).
- Phase stability (`chemthermo.stability`) is a solver-independent sibling of `chemthermo.flash`, and `flash_tp` consumes it twice: `flash_tp -> stability_tp -> split -> post-split stability` (ADR-0008, ADR-0009, ADR-0010), for phi-phi (EOS), gamma-gamma (activity, liquid-liquid) and modified-raoult (activity liquid + ideal vapor, VLE *or* LLE) alike. It serves all three through the internal `_TangentPlaneEvaluator` contract, which now holds a *set* of `_PhaseCandidate`s and keeps the lowest-Gibbs one at each composition (min-Gibbs cubic root; single liquid; liquid-versus-vapor). Each trial runs successive substitution then an optional damped-Newton stage.
- `Psat_i(T)` from the databank Antoine records lives in `src/chemthermo/models/_antoine.py` (internal), in the stored form `ln(P^sat/bar) = A - B/(T+C)`; it is the modified-Raoult reference fugacity and is refused outside each fit's stated range.
- Canonical runtime DB path is `src/chemthermo/data/components.json`.
- Runtime DB loading is package-resource based via `chemthermo.data` helpers.
- Raw DB source tables stay in `database/organics.txt` and `database/inorganics.txt`.
- `tools/build_database.py` is the canonical regeneration/check tool for packaged DB sync.
- Optional mirror output path is `database/components.mirror.json` (non-runtime, generated-only).
- Core thermodynamic flow is `Component/Composition/Mixture -> models -> flash_tp -> stability_tp -> seeded split (+ second-order stage for LLE) -> post-split stability -> add/remove phases up to max_phases -> FlashResult` (phi-phi, gamma-gamma and modified-raoult; the add/remove step is reached by phi-phi and modified-raoult only, ADR-0011 and ADR-0020). A phase set is a list of `(label, surface, composition)`: the surface is a phase candidate for the activity path and a pinned density root (`_PhaseRoot`) for an equation of state, which is what lets a three-phase EOS set hold two phases labelled `"liquid"`. gamma-phi still goes straight to the Wilson-seeded split and is not post-split checked.
- CLI `tp-flash` maps inputs to `Mixture + PengRobinsonEOS + flash_tp`, with optional `NRTL()` activity model when `--flash-mode gamma-phi`.
- CLI supports deterministic text/json outputs with schema version and diagnostics.
- External validation remains optional and script-driven (`examples/validation/00_reference_case.py`).

## Risks / unknowns
- ~~**PC-SAFT is honest only for non-associating, non-polar fluids.**~~ Association is implemented and validated as of ADR-0018, for the **2B** scheme only. What is left of this risk is narrower and still real: general `(na, nb)` site counts run but are cross-checked by nothing; **induced association** (a non-associating component solvating with an associating one) is not modelled at all, because it needs a cross `kappa` that is not a function of the pure-component ones; the **polar** terms are still absent, so a strongly polar non-associating compound still gets confident wrong numbers; and `PCSAFTParameters.from_records(...)` will still accept any parameters a caller invents.
- ~~**A liquid-liquid PC-SAFT split is only reachable where the vapour root has ceased to exist**~~ and ~~**when a phi-phi split *is* two liquids, they are named wrong**~~: **both resolved by ADR-0019.** Each phase now sits on the branch the stability test found it on, and a pair that both measure as liquids is named `liquid1` / `liquid2` with `vapor_fraction = None`. What replaces these two risks is narrower and real: **a phi-phi state that needs three phases still raises**. The post-split stability test proves the two-phase set wrong rather than returning it, so the failure stays loud, but the answer is not produced. Bracketed on water / n-hexane at 1 atm between 328 K (stable LLE) and 335 K (stable VLE); 330 K and 334 K raise. Case P-8, and the target of the next slice.
- **The association site fractions are an inner non-linear solve inside the density scan**, and its cost is real: a `density_roots` call for pure water is ~5.0 ms against ~2.5 ms for n-hexane. Convergence is measured (worst mass-action residual 4.4e-16 over the full 1599-point grid, 1000-state robustness sweep with zero `nan`s) but the iteration counts are fixed constants, so a pathological state would raise `AssociationParameterError` rather than silently return a half-converged `X`.
- **PC-SAFT's density root scan can miss a pair of roots that is narrower than its grid step** (`5e-4` in packing fraction), and the state is then reported with one root fewer. That happens only where the isotherm is nearly tangent to the target pressure - a near-critical or near-spinodal state - where the missed phase is physically marginal. The step is a named constant so the trade is explicit, not hidden (ADR-0015, Case P-3).
- **The `(T, rho, x)` methods still choose nothing**, and that is deliberate: between the spinodals `Z < 0` and `ln phi` does not exist, and a caller who picks a density on the wrong branch gets a valid-looking answer for a state they did not mean. Use `density_roots` or the `phase=` interface when the model should choose. Root *selection* stays with the phase-candidate machinery (`_select_min_gibbs`), not buried in the equation of state.
- **The residual `|P_model - P|/P` at a returned root is limited by cancellation, not by the iteration.** On a dense liquid branch at a low pressure `Z` is a near-total cancellation (1.17e-3 at n-hexane's 300 K saturation state), so a 1e-14 relative error in `a'` is 1e-11 in `P`. Measured 2.2e-14 at 10 MPa and 6.5e-12 at 21.9 kPa. The *density* is unaffected (2.2e-16 against teqp) and is what the tests pin; `DensityRoots.max_relative_residual` reports the number rather than hiding it.
- **`flash_tp` with PC-SAFT still stops at two phases**, like every phi-phi state (ADR-0009, ADR-0011), and no phase densities are carried in `FlashResult` - they have to be recomputed with `density_roots` at the converged composition.
- **PC-SAFT's parameter provenance is second hand, and so is the association *equation*.** Neither primary paper could be opened (ACS 403 for both DOI 10.1021/ie0003887 and DOI 10.1021/ie010954d). Two independent secondary sources agree digit for digit on every table, and teqp and FeOs reproduce the numbers, so a transcription error would have to be shared by teqp, FeOs, Clapeyron.jl and Wikipedia - but "verified against the paper" is *not* a claim this repository can make today. For association this goes one step further: the `sigma^3`-versus-`d^3` prefactor in `Delta` was decided by **numerical agreement with FeOs** (exact, against 8.9e-03 for the other spelling), not by reading the equation. That is strong evidence and it is the right convention *for these parameters*, but it is evidence, not a citation.
- **The universal constants differ between reference implementations.** FeOs carries the 2001 table to fourteen figures where the paper prints ten (difference up to 4.8e-09), which floors any FeOs comparison of a dispersion-dependent quantity at ~1e-9 (`Z`) to ~1e-6 (`ln phi`). chemthermo keeps the printed table, as teqp does. Anyone reading a FeOs-vs-chemthermo number must know which column it came from; Case P-6 reports both.
- **No PC-SAFT temperature derivative**, so no residual enthalpy/entropy and no cross-check against teqp's `get_Ar10`. That column of the comparison is empty and is recorded as empty in Case P-1.
- **The single-root fallback of ADR-0021 is counted at a trial's stopping point, not at every iterate.** `StabilityTrial.surface_fallback` therefore answers "did this trial stop where the model had one density root" (448 / 624 Peng-Robinson trials, 589 / 752 PC-SAFT), not "did it ever leave its surface". The un-instrumented answer to the second question - about **nine evaluations in ten** - was measured once with a both-branches build and recorded in ADR-0021 and Case P-11. It changes no result (where the model has one root, the pinned surface and the lowest-Gibbs surface are the same surface), but a reader who takes the diagnostic for the stronger claim would be wrong.
- **Near a three-phase state the modified-Raoult path refuses over a finite window, and its message is only half right.** Measured for water/1-butanol at 1 atm, z(butanol) = 0.20: from about T3 - 0.135 K up to T3 = 366.2138 K, the deepest tangent-plane minimum is the *vapor*, the split converges a vapor-liquid pair whose liquid lies inside the miscibility gap, and the post-split test raises "a third phase is required". Refusing is correct (that pair is not the equilibrium), but below T3 the resolution is a *different pair of two*, reached by adding the second liquid and then removing the vapor. `flash-vlle-phase-addition` must handle removal, not only addition. Validation Case R-3, ADR-0010 "Known limitation, measured".
- The modified-Raoult model is honest only at low pressure: ideal vapor (no `phi^V`), no Poynting correction, no `phi^sat`, and a temperature range bounded by the Antoine fits (enforced with `InputRangeError`, never extrapolated). Nothing in the code stops a user from calling it at 50 bar; the docs say not to, and the physics does not.
- `flash_tp` still returns at most two phases. A state needing a third is now *detected* by the post-split check and refused with `ConvergenceError`, not solved. Both the feed verdict and the post-split verdict inherit `stability_tp`'s bound: "stable" means nothing negative was found from the deterministic trial set, so a third phase no trial reaches would still be missed.
- The post-split check is only as sharp as the split it checks. Measured margin at default settings is large (worst post-split `tpd_min` -7.0e-09 against `tpd_tol` 1e-8 - a factor of 1.4 - with the minimizer matching the partner phase to `sum ln(w/x)^2 <= 4e-16`, twelve orders inside `trivial_tol`), but with a deliberately loosened `FlashSettings(tol=1e-3)` a genuinely two-phase state is reported as needing a third phase. Documented in README and ADR-0009.
- Every two-phase flash on the tangent-plane paths now pays for two extra stability analyses (measured: 0.9 s for the 47 two-phase states of the in-repo grid, roughly doubling their cost). There is no way to skip the computation, only the raise.
- `liquid1`/`liquid2` carry no physical identity and can swap between feeds on the same tie-line. Any consumer that indexes `result.phases["liquid1"]` expecting a particular liquid is wrong.
- The vapor/liquid *name* of a `flash_tp` phase is a convention in two places: a single-root (dense/supercritical) single-phase feed gets whichever branch label wins the min-Gibbs tie-break, and a two-phase result is named by Wilson volatility ranking. `EquationOfState` exposes no molar volume, so nothing better is available without widening that protocol.
- Every phi-phi flash now pays for a stability analysis (2 Wilson trials + 1 pure trial per component) even for an obviously single-phase feed.
- 5 states in the 1144-state scan (Methane/Propane/n-Decane 0.7/0.2/0.1 at 1.2e7-2.0e7 Pa) split in chemthermo (`delta_g_split_rt < 0`) while `thermo`'s `FlashVL` returns `VF = 0`. They disagreed with `thermo` before this slice too, so they are not caused by it. Now adjudicated: evaluating `thermo`'s own `lnphis_at_zs(..., most_stable=True)` at chemthermo's `stability_tp` minimizer gives a negative tpd (within 5e-5 abs of chemthermo's `tpd_min`) at all 5 states, so `thermo`'s `VF = 0` is a stability-*search* miss on `thermo`'s side, not a chemthermo error. See Case F-1 in `validation-cases.md` and `tests/validation/test_flash_thermo_disagreements_adjudicated.py`.
- `stability_tp` reporting "stable" is bounded by its deterministic trial set; it is not a global proof, and the docs must keep saying so. Measured limit: on Tessier (2000) Problem 2 the trial set reaches 7 of the 10 non-trivial published stationary points; the three it misses all have D > 0 (Cases S-6, S-7).
- Combined gamma-phi stability (activity liquid vs EOS vapor) raises `ModelError`. It stays unsupported until there is a consistent pure-liquid reference fugacity (ADR-0007); the current gamma-phi flash does not carry one correctly.
- The second-order stage uses a central-difference Jacobian of `ln phi`/`ln gamma`. For a cubic EOS the branch selected for a phase can switch between finite-difference probes, which would make that Jacobian noisy. **One Peng-Robinson state now enters the stage** (methane/ethane/propane at 290 K / 8 MPa, ADR-0016) and converges cleanly to a `fugacity_residual` of 1.8e-15, so the risk is no longer purely hypothetical but has not bitten. Note that on the phi-phi path the two phases are evaluated on *fixed* labelled branches (`phase="liquid"` / `phase="vapor"`), not by re-selecting the min-Gibbs branch at each probe, which is what should keep the Jacobian smooth. Watch for it as more PR or PC-SAFT states reach the stage.
- The phi-phi second-order stage has been measured on exactly **five** states (four PC-SAFT, one Peng-Robinson). There is no claim that it always succeeds; a failure is still a `ConvergenceError`, now naming both stages' iteration counts.
- chemthermo uses the rounded PR constants 0.45724 / 0.07780 while `thermo` uses the exact roots; this bounds external agreement at a few times 1e-4 in ln(phi) (was ~2e-4 at the stability states, ~4-6e-4 at some nonzero-kij states -- see Case K-1).
- The illustrative kij value used in docs/examples/tests (0.0411, Methane/n-Decane) is explicitly NOT a validated literature parameter -- do not let it drift into being read as one.
- `thermo`'s own `CEOSLiquid`/`CEOSGas` root solver was observed to be numerically order-sensitive (not permutation-invariant) at some near-critical-locus states during `pr-kij-matrix` development; avoid cross-checking permutation invariance against `thermo` at such states (use chemthermo-internal invariance checks instead, as `tests/validation/test_pr_kij_vs_thermo.py` now does).
- CLI JSON contract must remain backward-compatible or version-bumped.
- DB builder currently assumes raw table column conventions stay unchanged.
- Optional validation still depends on external `thermo` package availability.
- (Removed) Unpinned `bibtexparser>=1.4.0` allowed a fresh/non-editable install to resolve `bibtexparser` 2.x, whose removed `bparser`/`customization` modules broke `import chemthermo`; this was invisible locally because the dev venv already had 1.4.4 installed. Now pinned to `>=1.4.0,<2` and covered by `tests/test_packaging_constraints.py`.

## Next 3 recommended actions
- **`pcsaft-polymer-parameters` (Stage H), recommended next and *before* the performance slice.** The PC-SAFT parameter layer packages 16 small molecules keyed by compound name; polymers need `m/M` (segments per unit mass) and a molar-mass-dependent chain length, which `PCSAFTRecord` / `PCSAFTParameters.from_records` cannot express. Do it first because it is the last *capability* gap that changes a **public data contract**, and a contract change is far cheaper before the code is tuned than after - profiling and then re-profiling around a schema change throws the baseline away. It also has the external reference every PC-SAFT slice here has depended on (FeOs and Clapeyron both carry polymer parameter sets). Keep every existing record bit-identical.
- **`perf-profile-baseline` (Stage I), second.** There is no performance baseline anywhere in this repository and three ADRs in a row have recorded "no performance work was done". Now measured: a three-phase PC-SAFT flash costs ~35 s and makes **4,725** `fugacity_coefficients` calls, each a full 1,599-point density-root scan, roughly half of them inside the multiphase second-order stage's finite-difference Hessian. The two obvious wins - caching density roots per `(T, P, x)` within one flash, and a structured Hessian for the multiphase stage - touch exactly the `PCSAFTEOS` call path Stage H changes, which is why this goes second. Pin **call counts**, not only seconds, so the baseline survives a change of machine.
- **Phase densities in `FlashResult`.** Still open, still a schema change rather than a new measurement: both packaged models already compute the density of the root each phase converged on (`PCSAFTEOS.density_roots`, `PengRobinsonEOS.compressibility_factor`, and `phase_identity` internally). Every PC-SAFT example currently recomputes it by hand, which is the smell.
- **A PC-SAFT temperature derivative.** The only gap that blocks a whole *class* of outputs rather than a case: no residual enthalpy or entropy, no caloric properties, no cross-check against teqp's `get_Ar10`, and no access to the Venkatarathnam-Oellrich `Pi` criterion ADR-0017 had to reject for want of it. It is a second analytic derivative chain through hard chain, dispersion **and** now association (where Michelsen-Hendriks again makes the first `T` derivative an explicit partial of `Q`, so it is less work than it looks).

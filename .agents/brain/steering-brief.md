  - **The thing ADR-0023 rejected, built in the one place where its reasons do not apply.** ADR-0023 turned down "cache the last root solve on the model instance" because both model classes are frozen dataclasses, a hidden mutable cache makes them stateful and thread-unsafe, and a stale key would be a *wrong answer* rather than a slow one. All of that is still true of a cache on a model. None of it is true of a memo that lives in the **call**: `chemthermo._eos_memo` is a bounded FIFO behind a `ContextVar`, installed by a decorator on `flash_tp` / `stability_tp` and reset in a `finally`, with a nested `stability_tp` reusing the flash's rather than opening a second. Nothing is written to a model, nothing outlives the call, and two threads cannot share one.
  - **Bit-identity is object identity, not arithmetic.** A hit returns the *same object* the first solve produced, so every double downstream of it is the same double. The whole risk is therefore concentrated in the key, and one pair of distinct bit patterns can alias in Python: `-0.0` and `0.0` compare equal and hash equal. `composition_key` separates them. `nan` misses by definition; `id(model)` is held alive by the entry that uses it; the 4096-entry bound can only cost a re-solve.

## Current architecture (8-12 lines)
- `chemthermo.eos.PCSAFTEOS` speaks **both** state specifications: `(T, molar density, x)` in for `A^res/RT` / `Z` / `P` / `ln phi_i` (ADR-0014), and `(T, P, x, phase)` in for `fugacity_coefficients` / `density_roots` / `molar_volume` (ADR-0015), the latter solving `P_model = P` for its mechanically stable roots in the private `eos/_pcsaft_density.py` (the model restricted to one `(T, x)` is a function of the packing fraction alone, which makes the scan vectorizable and `dP/drho` analytic). Because it now satisfies `chemthermo.models.EquationOfState`, it joins the flash and the stability test **through the same interface Peng-Robinson uses and with no solver change**: `_EOSTangentPlane`'s existing lowest-Gibbs selection over the `"vapor"` / `"liquid"` branches is already the right rule for density roots. It shares the `kij` contract with Peng-Robinson through the internal `models/_kij.py`.
- `NRTL` implements the standard Renon-Prausnitz equation (column sums); it satisfies Gibbs-Duhem to ~2e-10 and matches `thermo` to ~9e-16 with asymmetric parameters. Packaged pair parameters are synthetic placeholders; published sets live in `tests/fixtures/`.
- `PengRobinsonEOS.kij` is a scalar (off-diagonal only) or a name-keyed per-pair `Mapping`; `flash_tp` and `stability_tp` results for nonzero kij are now trustworthy (ADR-0006).
- Phase stability (`chemthermo.stability`) is a solver-independent sibling of `chemthermo.flash`, and `flash_tp` consumes it twice: `flash_tp -> stability_tp -> split -> post-split stability` (ADR-0008, ADR-0009, ADR-0010), for phi-phi (EOS), gamma-gamma (activity, liquid-liquid) and modified-raoult (activity liquid + ideal vapor, VLE *or* LLE) alike. It serves all three through the internal `_TangentPlaneEvaluator` contract, which now holds a *set* of `_PhaseCandidate`s and keeps the lowest-Gibbs one at each composition (min-Gibbs cubic root; single liquid; liquid-versus-vapor). Each trial runs successive substitution then an optional damped-Newton stage.
- `Psat_i(T)` from the databank Antoine records lives in `src/chemthermo/models/_antoine.py` (internal), in the stored form `ln(P^sat/bar) = A - B/(T+C)`; it is the modified-Raoult reference fugacity and is refused outside each fit's stated range.
- Canonical runtime DB path is `src/chemthermo/data/components.json`.
- Runtime DB loading is package-resource based via `chemthermo.data` helpers.
- Raw DB source tables stay in `database/organics.txt` and `database/inorganics.txt`.
- `tools/build_database.py` is the canonical regeneration/check tool for packaged DB sync.
- Optional mirror output path is `database/components.mirror.json` (non-runtime, generated-only).
- Core thermodynamic flow is `Component/Composition/Mixture -> models -> flash_tp -> stability_tp -> seeded split (+ second-order stage for LLE) -> post-split stability -> add/remove phases up to max_phases -> FlashResult` (phi-phi, gamma-gamma and modified-raoult; the add/remove step is reached by phi-phi and modified-raoult only, ADR-0011 and ADR-0020). A phase set is a list of `(label, surface, composition)`: the surface is a phase candidate for the activity path and a pinned density root (`_PhaseRoot`) for an equation of state, which is what lets a three-phase EOS set hold two phases labelled `"liquid"`. gamma-phi still goes straight to the Wilson-seeded split and is not post-split checked.
- CLI `tp-flash` maps inputs to `Mixture + PengRobinsonEOS + flash_tp`, with optional `NRTL()` activity model when `--flash-mode gamma-phi`.
- CLI supports deterministic text/json outputs with schema version and diagnostics.
- External validation remains optional and script-driven (`examples/validation/00_reference_case.py`).

## Risks / unknowns
- **"Bit-identical" is a same-platform statement (ADR-0032).** Captured-value
  guards are exact only on macOS arm64; CI and cloud sessions check discrete
  fields exactly and floats to 1e-12 / 5e-14. A numerical change smaller than
  that bound is caught only on the capture machine. In-process A/B guards stay
  exact everywhere.
- **Chaotic routes on diverged K-loop states.** Where successive substitution
  diverges (the ADR-0028 ladder states), which rung finishes - and, at 1 of 17
  measured neighbouring pressures, whether any does - depends on the last bit.
  Grid-point robustness counts are therefore machine-dependent near those
  states (ledger Case P-17 "cross-platform").
- **The map is hard again, and still bounded by what it sweeps (ADR-0027
  amendment).** The 2505-state sweep at `74820b8` found 14 refusals in the
  four families slice `robustness-map-coverage` added - none in the original
  six, which are unchanged field for field. Six of the eight declared refusal
  classes are still empty, no state anywhere uses `max_phases > 3`, and
  `pr-near-critical` (built to find something near a boundary) found nothing.
  Quote it as "nothing in *this* grid refuses", never as a coverage claim.
  (Case R-MAP-1, Case P-17, Case R-MAP-2.)
- **The ADR-0028 seed ladder has three entries because three defects were
  measured**, and a fourth geometry may need a fourth. The first two entries
  are the calls that were already there and the third is a new seed, so the
  cost of finding out is one more `log_space_split` attempt on a path that was
  about to raise anyway.
- **A refused state used to be cheap.** A state that now converges through the
  ladder pays for every attempt before the one that worked, and a stability
  retry pays for a second full set of trials: the two 15 wt% polymer states are
  the 4th and 5th slowest in the whole map (8.8 s and 8.4 s) and the `polymer`
  family's sweep time rose 311.9 s -> 352.1 s for 36 more answers.
- ~~**PC-SAFT is honest only for non-associating, non-polar fluids.**~~ Association is implemented and validated as of ADR-0018, for the **2B** scheme only. What is left of this risk is narrower and still real: general `(na, nb)` site counts run but are cross-checked by nothing; **induced association** (a non-associating component solvating with an associating one) is not modelled at all, because it needs a cross `kappa` that is not a function of the pure-component ones; the **polar** terms are still absent, so a strongly polar non-associating compound still gets confident wrong numbers; and `PCSAFTParameters.from_records(...)` will still accept any parameters a caller invents.
- ~~**A liquid-liquid PC-SAFT split is only reachable where the vapour root has ceased to exist**~~ and ~~**when a phi-phi split *is* two liquids, they are named wrong**~~: **both resolved by ADR-0019.** Each phase now sits on the branch the stability test found it on, and a pair that both measure as liquids is named `liquid1` / `liquid2` with `vapor_fraction = None`. What replaces these two risks is narrower and real: **a phi-phi state that needs three phases still raises**. The post-split stability test proves the two-phase set wrong rather than returning it, so the failure stays loud, but the answer is not produced. Bracketed on water / n-hexane at 1 atm between 328 K (stable LLE) and 335 K (stable VLE); 330 K and 334 K raise. Case P-8, and the target of the next slice.
- **The association site fractions are an inner non-linear solve inside the density scan**, and its cost is real: a `density_roots` call for pure water is ~5.0 ms against ~2.5 ms for n-hexane. Convergence is measured (worst mass-action residual 4.4e-16 over the full 1599-point grid, 1000-state robustness sweep with zero `nan`s) but the iteration counts are fixed constants, so a pathological state would raise `AssociationParameterError` rather than silently return a half-converged `X`.
- **PC-SAFT's density root scan can miss a pair of roots that is narrower than its grid step** (`5e-4` in packing fraction), and the state is then reported with one root fewer. That happens only where the isotherm is nearly tangent to the target pressure - a near-critical or near-spinodal state - where the missed phase is physically marginal. The step is a named constant so the trade is explicit, not hidden (ADR-0015, Case P-3).
- **The `(T, rho, x)` methods still choose nothing**, and that is deliberate: between the spinodals `Z < 0` and `ln phi` does not exist, and a caller who picks a density on the wrong branch gets a valid-looking answer for a state they did not mean. Use `density_roots` or the `phase=` interface when the model should choose. Root *selection* stays with the phase-candidate machinery (`_select_min_gibbs`), not buried in the equation of state.
- **The residual `|P_model - P|/P` at a returned root is limited by cancellation, not by the iteration.** On a dense liquid branch at a low pressure `Z` is a near-total cancellation (1.17e-3 at n-hexane's 300 K saturation state), so a 1e-14 relative error in `a'` is 1e-11 in `P`. Measured 2.2e-14 at 10 MPa and 6.5e-12 at 21.9 kPa. The *density* is unaffected (2.2e-16 against teqp) and is what the tests pin; `DensityRoots.max_relative_residual` reports the number rather than hiding it.
- **`flash_tp` with PC-SAFT still stops at two phases**, like every phi-phi state (ADR-0009, ADR-0011), and no phase densities are carried in `FlashResult` - they have to be recomputed with `density_roots` at the converged composition.
- **The polymer parameters this package's tests and examples use rest on a single secondary source.** ADR-0022 ships *no* polymer parameters; the polyethylene / polypropylene / polystyrene values live in a test fixture, as tabulated by Martini et al. (2009) citing a paywalled Gross & Sadowski (2002) table that was **not read**, with no second open source found (FeOs and Clapeyron.jl carry none). That is a weaker footing than every other parameter in this repository, and it is the reason they are a fixture rather than packaged data. Anyone using the polymer capability must supply and cite their own.
- **A polymer here is monodisperse.** One chain length, one component. Real samples are not - the ones these parameters describe have polydispersities of 1.14 to 2.94 - so a chemthermo answer is the single-chain-length idealization of a sample, not the sample. Pseudo-component distributions are a capability this package does not have (`pcsaft-polydispersity`).
- ~~**The phi-phi split does not converge for a polymer/solvent system below the solvent's saturation pressure**~~ **Resolved by ADR-0024**: the split is seeded and finished in log mole numbers there, and both pinned states (binary at 1 and 2 MPa, ternary at 3 MPa) now return verified answers (Case P-14). ~~What is left is narrower and sits **upstream**, in the stability module: for `Mw = 53000` (`m = 1393.9`) at 0.5 and 1 MPa the deterministic trial set's deepest stationary point is a shallow *vapour-side* one and the melt is missed entirely.~~ **Also resolved, by ADR-0025**: it was not the trial set but the `[-700, 700]` clamp on `ln W`, the melt's stationary point being at `ln W_polymer = 1452.21`. With the normalization done in logarithms the melt is the minimizer and `flash_tp` returns a verified split at every pressure from 0.4 to 2.0 MPa (13 states that raised now converge; Case P-15). What is left is narrower still and is recorded in ADR-0025: the second-order stage at `|ln W| ~ 1e3` is untested because every repaired state converges in 3 successive substitutions, and 0.3 MPa and 2.8-3.2 MPa of the same system still raise inside the split stage with `ln W` comfortably in range.
- **A fugacity coefficient can leave the exponential's range, and the guard that handles it is only as good as the models that implement it.** `EquationOfState.log_fugacity_coefficients` defaults to `None`, so a third-party EOS that does not implement it reproduces the pre-ADR-0022 refusal exactly. `PengRobinsonEOS` does not implement it and does not need to (no cubic reaches `|ln phi| > 709` on any validated state), but that is a measurement about this repository's grids, not a theorem.
- **PC-SAFT's parameter provenance is second hand, and so is the association *equation*.** Neither primary paper could be opened (ACS 403 for both DOI 10.1021/ie0003887 and DOI 10.1021/ie010954d). Two independent secondary sources agree digit for digit on every table, and teqp and FeOs reproduce the numbers, so a transcription error would have to be shared by teqp, FeOs, Clapeyron.jl and Wikipedia - but "verified against the paper" is *not* a claim this repository can make today. For association this goes one step further: the `sigma^3`-versus-`d^3` prefactor in `Delta` was decided by **numerical agreement with FeOs** (exact, against 8.9e-03 for the other spelling), not by reading the equation. That is strong evidence and it is the right convention *for these parameters*, but it is evidence, not a citation.
- **The universal constants differ between reference implementations.** FeOs carries the 2001 table to fourteen figures where the paper prints ten (difference up to 4.8e-09), which floors any FeOs comparison of a dispersion-dependent quantity at ~1e-9 (`Z`) to ~1e-6 (`ln phi`). chemthermo keeps the printed table, as teqp does. Anyone reading a FeOs-vs-chemthermo number must know which column it came from; Case P-6 reports both.
- **No PC-SAFT temperature derivative**, so no residual enthalpy/entropy and no cross-check against teqp's `get_Ar10`. That column of the comparison is empty and is recorded as empty in Case P-1.
- **The single-root fallback of ADR-0021 is counted at a trial's stopping point, not at every iterate.** `StabilityTrial.surface_fallback` therefore answers "did this trial stop where the model had one density root" (448 / 624 Peng-Robinson trials, 589 / 752 PC-SAFT), not "did it ever leave its surface". The un-instrumented answer to the second question - about **nine evaluations in ten** - was measured once with a both-branches build and recorded in ADR-0021 and Case P-11. It changes no result (where the model has one root, the pinned surface and the lowest-Gibbs surface are the same surface), but a reader who takes the diagnostic for the stronger claim would be wrong.
- **Near a three-phase state the modified-Raoult path refuses over a finite window, and its message is only half right.** Measured for water/1-butanol at 1 atm, z(butanol) = 0.20: from about T3 - 0.135 K up to T3 = 366.2138 K, the deepest tangent-plane minimum is the *vapor*, the split converges a vapor-liquid pair whose liquid lies inside the miscibility gap, and the post-split test raises "a third phase is required". Refusing is correct (that pair is not the equilibrium), but below T3 the resolution is a *different pair of two*, reached by adding the second liquid and then removing the vapor. `flash-vlle-phase-addition` must handle removal, not only addition. Validation Case R-3, ADR-0010 "Known limitation, measured".
- The modified-Raoult model is honest only at low pressure: ideal vapor (no `phi^V`), no Poynting correction, no `phi^sat`, and a temperature range bounded by the Antoine fits (enforced with `InputRangeError`, never extrapolated). Nothing in the code stops a user from calling it at 50 bar; the docs say not to, and the physics does not.
- `flash_tp` still returns at most two phases. A state needing a third is now *detected* by the post-split check and refused with `ConvergenceError`, not solved. Both the feed verdict and the post-split verdict inherit `stability_tp`'s bound: "stable" means nothing negative was found from the deterministic trial set, so a third phase no trial reaches would still be missed.
- The post-split check is only as sharp as the split it checks. Measured margin at default settings is large (worst post-split `tpd_min` -7.0e-09 against `tpd_tol` 1e-8 - a factor of 1.4 - with the minimizer matching the partner phase to `sum ln(w/x)^2 <= 4e-16`, twelve orders inside `trivial_tol`), but with a deliberately loosened `FlashSettings(tol=1e-3)` a genuinely two-phase state is reported as needing a third phase. Documented in README and ADR-0009.
- Every two-phase flash on the tangent-plane paths now pays for two extra stability analyses (measured: 0.9 s for the 47 two-phase states of the in-repo grid, roughly doubling their cost). There is no way to skip the computation, only the raise.
- `liquid1`/`liquid2` carry no physical identity and can swap between feeds on the same tie-line. Any consumer that indexes `result.phases["liquid1"]` expecting a particular liquid is wrong.
- The vapor/liquid *name* of a `flash_tp` phase is a convention in two places: a single-root (dense/supercritical) single-phase feed gets whichever branch label wins the min-Gibbs tie-break, and a two-phase result is named by Wilson volatility ranking. `EquationOfState` exposes no molar volume, so nothing better is available without widening that protocol.
- Every phi-phi flash now pays for a stability analysis (2 Wilson trials + 1 pure trial per component) even for an obviously single-phase feed.
- 5 states in the 1144-state scan (Methane/Propane/n-Decane 0.7/0.2/0.1 at 1.2e7-2.0e7 Pa) split in chemthermo (`delta_g_split_rt < 0`) while `thermo`'s `FlashVL` returns `VF = 0`. They disagreed with `thermo` before this slice too, so they are not caused by it. Now adjudicated: evaluating `thermo`'s own `lnphis_at_zs(..., most_stable=True)` at chemthermo's `stability_tp` minimizer gives a negative tpd (within 5e-5 abs of chemthermo's `tpd_min`) at all 5 states, so `thermo`'s `VF = 0` is a stability-*search* miss on `thermo`'s side, not a chemthermo error. See Case F-1 in `validation-cases.md` and `tests/validation/test_flash_thermo_disagreements_adjudicated.py`.
- `stability_tp` reporting "stable" is bounded by its deterministic trial set; it is not a global proof, and the docs must keep saying so. Measured limit: on Tessier (2000) Problem 2 the trial set reaches 7 of the 10 non-trivial published stationary points; the three it misses all have D > 0 (Cases S-6, S-7).
- Combined gamma-phi stability (activity liquid vs EOS vapor) raises `ModelError`. It stays unsupported until there is a consistent pure-liquid reference fugacity (ADR-0007); the current gamma-phi flash does not carry one correctly.
- The second-order stage uses a central-difference Jacobian of `ln phi`/`ln gamma`. For a cubic EOS the branch selected for a phase can switch between finite-difference probes, which would make that Jacobian noisy. **One Peng-Robinson state now enters the stage** (methane/ethane/propane at 290 K / 8 MPa, ADR-0016) and converges cleanly to a `fugacity_residual` of 1.8e-15, so the risk is no longer purely hypothetical but has not bitten. Note that on the phi-phi path the two phases are evaluated on *fixed* labelled branches (`phase="liquid"` / `phase="vapor"`), not by re-selecting the min-Gibbs branch at each probe, which is what should keep the Jacobian smooth. Watch for it as more PR or PC-SAFT states reach the stage.
- The phi-phi second-order stage has been measured on exactly **five** states (four PC-SAFT, one Peng-Robinson). There is no claim that it always succeeds; a failure is still a `ConvergenceError`, now naming both stages' iteration counts.
- chemthermo uses the rounded PR constants 0.45724 / 0.07780 while `thermo` uses the exact roots; this bounds external agreement at a few times 1e-4 in ln(phi) (was ~2e-4 at the stability states, ~4-6e-4 at some nonzero-kij states -- see Case K-1).
- The illustrative kij value used in docs/examples/tests (0.0411, Methane/n-Decane) is explicitly NOT a validated literature parameter -- do not let it drift into being read as one.
- `thermo`'s own `CEOSLiquid`/`CEOSGas` root solver was observed to be numerically order-sensitive (not permutation-invariant) at some near-critical-locus states during `pr-kij-matrix` development; avoid cross-checking permutation invariance against `thermo` at such states (use chemthermo-internal invariance checks instead, as `tests/validation/test_pr_kij_vs_thermo.py` now does).
- CLI JSON contract must remain backward-compatible or version-bumped.
- DB builder currently assumes raw table column conventions stay unchanged.
- Optional validation still depends on external `thermo` package availability.
- (Removed) Unpinned `bibtexparser>=1.4.0` allowed a fresh/non-editable install to resolve `bibtexparser` 2.x, whose removed `bparser`/`customization` modules broke `import chemthermo`; this was invisible locally because the dev venv already had 1.4.4 installed. Now pinned to `>=1.4.0,<2` and covered by `tests/test_packaging_constraints.py`.
